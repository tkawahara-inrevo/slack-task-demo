## 1. TaskHub とは

**TaskHub**（社内通称: **Pochi / ポチ**）は INREVO 社のオールインワン業務管理システムです。

Slack に常駐する Pochi bot と、専用 Web ダッシュボード（https://inrevo-task.com）の2つの入口があり、両方が同じデータを見ています。

### できること（ざっくり）
- タスクの作成・依頼・進捗管理（個人タスク / 一斉タスク）
- 電子決裁の起票・承認
- 営業案件（CRM）の管理
- RPO 案件（採用代行）の管理
- 自社採用の応募者管理
- 法務・AN（見積依頼）の管理
- 工数（Workload）の入力・Gantt 表示
- HRMOS 勤怠の自動打刻（出退勤日報チャンネル経由）
- kintone との自動同期
- Claude AI によるスレッド要約・質問応答

### 関連 Slack ボット
| ボット名 | 役割 |
|---|---|
| **Pochi / ポチ** | TaskHub のメイン bot。タスク・決裁・通知・要約など全機能 |
| **daily-report-watcher** | 出退勤日報の未提出者をリスト化（朝に投稿） |
| **slack-relay-bot** | 補助リレー用 |

## 3. タスク機能

### 3.1 タスクの種類
| 種類 | 説明 |
|---|---|
| **個人タスク（personal）** | 1人にお願いするタスク |
| **一斉タスク（broadcast）** | 複数人に同じタスクを配って、それぞれの完了状況を追える |

### 3.2 タスクの作成方法

#### Slack 上で
1. **メッセージから**: 任意のメッセージにマウスホバー → ⋯メニュー → 「タスク作成」ショートカット
2. **ホームタブ**: Pochi の App Home を開く → 「タスクを作成」ボタン
3. **キーワード自動化**: 自分の `/my-settings` でキーワードを登録すると、それを含む投稿は自動でタスク化されます

#### Web 上で
- サイドバー → 「タスク」→「新規作成」
- タイトル、説明、期限、担当者、グループを入力

### 3.3 デフォルトの期限ルール
- 期限を指定せずに作成した場合:
  - **JST 15:00 までに作成** → 当日が期限
  - **JST 15:00 以降に作成** → 翌日が期限
- 時刻指定（time_of_day）も可能

### 3.4 タスクを完了する
- Slack カードの **完了ボタン**
- もしくはタスク投稿に **:済: リアクション**（双方向で同期）
- 完了後も「戻す」ボタンで未完了に戻せます

### 3.5 一斉タスクの進捗
- 投稿された一斉タスクには「進捗確認」ボタンがあり、未完了者一覧モーダルが開きます
- 「対象者から外す」「未完了者に DM で再通知」ボタンも使えます
- 全員完了したら「全員完了」ボタン（確認ダイアログあり）

### 3.6 タスクのリマインド
Pochi は自動で DM を送ります:
- **朝（7:00〜11:00 の10分毎）**: 期限切れと当日期限を **1通の集約 DM** にまとめて送付
- **昼（11:00）**: リマインド
- **午後（16:00）**: リマインド
- 営業日のみ実施（土日・祝日はスキップ）

### 3.7 ホームタブ（Pochi App Home）
Pochi をクリックして表示される画面。
- マイタスク一覧
- フィルター（自分宛 / 依頼した / 全部、進行中 / 完了 / 全部、部署別、ステータス）
- 表示モード切替（標準 / コンパクト）
- 個人フィルター保存
- ダッシュボードへの遷移ボタン

## 4. 電子決裁

### 4.1 起票方法
- Slack で `/pochi-approval` コマンド
- もしくは決裁したいメッセージから **「電子決裁を起票」ショートカット**（スレッド内でも可）
- ホームから「電子決裁を起票」グローバルショートカット

### 4.2 入力項目
- タイトル、説明（クリックメッセージがあればその内容を初期セット）
- 承認者（複数選択可）
- **承認モード**: 並列 / 順次
  - **並列**: 全員に同時に通知、誰が承認・否認しても OK
  - **順次**: 1人ずつ順番に承認。順序変更は専用モーダル

### 4.3 承認・否認
- 通知された人は **「承認」「否認」ボタン**
- 否認は理由コメント必須

### 4.4 一覧確認
Web で「電子決裁」画面。承認待ち / 完了 / 否認のタブで絞り込み、Slack スレッドへのリンク付き。

## 5. CRM（営業案件管理）

### 5.1 画面構成
| 画面 | 用途 |
|---|---|
| **Leads Dashboard** | 受注確度別（S/A/B/C/D/E/商談前）の漏斗、ドリルダウン、CRM 同期ステータス |
| **Customers**（顧客管理） | 検索・フィルター、ページング、セールス担当別表示、顧客 CRUD |
| **Pipeline**（旧 Kanban） | ステージ別カード（アポ化前〜S 90%）、ドラッグ&ドロップ |
| **CRM Dashboard** | 月次サマリー、KPIカード、売上トレンド、チャネル別実績、代表者別比較 |

### 5.2 期間モード（ダッシュボード）
- **今期** / **前期** / **範囲指定**（月単位） / **任意期間**
- 「期繰越」ボタンで今期目標を前期目標へコピー（決算後に1回押す運用）
- 前前期以前を範囲指定 or 前期目標未設定の場合は KPI 達成率カードを非表示

### 5.3 kintone との関係
- App102（案件）と App170（入金確定）が **30分ごとに自動同期**
- 手動同期もできます（admin のみ）
- **入金確定額** は kintone App170 の `incentive_amount` が信頼源
- **方針**: 今後 TaskHub がデータマスターになり、kintone は移行期間中の参照のみ

### 5.4 顧客・商談
- 顧客（customers）と商談（deals）は分離管理
- 1顧客に複数商談を紐付け可
- 商談には: ヨミ（受注確度）、ステータス、初回面談日、受注日、活動履歴、サブテーブル（RPO コスト / 採用コスト / 労務コスト / 応募予測）
- 案件詳細モーダルからメモ追記、kintone レコードリンクへ飛べる
- 「見送り」化（dormant）可能

### 5.5 営業活動
- 案件詳細から **活動履歴** を追加（タイプ・結果・コメント・次回アクション）
- kintone 側の App103 活動履歴も統合表示

## 8. HRMOS 勤怠連携

### 8.1 自動打刻（出退勤日報チャンネル）
- **出勤日報チャンネル** に投稿 → Pochi が **60秒後に HRMOS へ出勤打刻**
- **退勤日報チャンネル** に投稿 → Pochi が **10分後に HRMOS へ退勤打刻**
- 60秒/10分の遅延がある理由: 投稿の取り消し・修正の余地を残すため
- 二重打刻防止チェック付き

### 8.2 前日退勤の遅出し対応
- 朝に「すみません昨日退勤忘れました」と退勤日報を投稿しても、Pochi は誤って打刻しません
- 検知条件: 昨日の出勤打刻あり / 昨日の退勤打刻なし / 今日の出勤打刻から2時間未満
- ⏪ リアクションを付けて「HRMOS 手動打刻のお願い」をスレッドに案内

### 8.3 月次チェック画面
- 管理画面 → HRMOS チェック
- 月単位で全員の打刻状況を一覧確認
- 除外ユーザーの登録（業務委託など打刻不要の人）

### 8.4 日報未提出者の自動仕分け（NEW）
朝に daily-report-watcher が「未提出者リスト」を投稿すると、Pochi が **自動でスレッドに仕分け返信** します。

**3つのカテゴリ**:

| カテゴリ | 条件 | 説明 |
|---|---|---|
| 📝 出すべき | HRMOS の勤務区分が出勤系 + 出勤打刻あり | 実際に勤務しているのに日報を出してない人。HR は **ここだけ対応** すれば OK |
| ❓ 要確認 | HRMOS の勤務区分が出勤系 + 出勤打刻なし | 急な欠勤 or 打刻忘れの可能性。状況確認が必要 |
| 🏖️ 休暇確認済み | HRMOS の勤務区分が公休/有給/祝日など | 事前に休暇登録済み。対応不要 |

- メンション化はしないので関係ない人を巻き込みません
- 出勤日報 = 当日のデータ、退勤日報 = 前日のデータをチェック

## 15. よくある質問

### Q. パスワードを忘れました
A. パスワード認証はありません。Slack で `/dashboard` を打ち直してください。

### Q. タスクが消えてしまった
A. 完了タスクは「完了」フィルターで再表示できます。削除されているわけではありません。

### Q. 出勤日報を投稿したら 60秒後に取り消したいです
A. その60秒の間に取り消せば打刻は行われません。

### Q. HRMOS が反映されていません
A. HRMOS の daily API は遅延があるため、リアルタイム反映ではない場合があります。月次チェック画面で確認してください。

### Q. CRM の数字が kintone と違います
A. kintone は30分ごとの同期です。手動同期ボタン（admin のみ）で即時更新できます。

### Q. メンションが鬱陶しいです
A. 仕分け機能などは原則メンションを付けない設計です。タスク通知の DM 自体は `/my-settings` から OFF にできます。

### Q. スレッド内でスラッシュコマンドが動きません
A. Slack の仕様です。代わりに **「電子決裁を起票」ショートカット** などのメッセージショートカットを使ってください。

## 16. データの扱いと方針

- **TaskHub がデータマスター**: 今後の入力は TaskHub 側で完結する方針
- **kintone は移行期間中の参照のみ**: 同期は片方向（kintone → TaskHub）
- **個人情報の取り扱い**: 採用候補者・社員情報は権限管理で保護
- **データバックアップ**: PostgreSQL の標準バックアップ運用
