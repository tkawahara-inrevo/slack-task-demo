# TaskHub ロードマップ
> 最終更新: 2026-05-02

---

## システムの目的

1. **INREVO社内ツール** — 申請・管理業務をすべてここに集約。外部ツールの情報もここで確認できる。
2. **ヒトトレ事業サポート** — MK→BC→HR→DR/CSの全フローをシステム上で完結できるようにする。

---

## 業務フロー全体図

```
【リード獲得】MK
  広告 / 架電（問い合わせ経由） / アライアンス / 販売代理店
  ↓ アポ確定
【商談】BC
  商談 → 追客 → 受注 or 失注
  ↓ 受注
【受注後準備】CR / ST / AN
  カルテ取得 → 登記・媒体分析 → DRへ引き継ぎ
  ↓
【採用活動】DR / CS / OP
  DR：顧客折衝・CSタスク管理
  CS：媒体運用・応募者対応・軌道修正
  OP：求人作成

【横断】経理・総務
  入出金管理 / 請求書・契約書 / 反社チェック
```

## 優先度別ロードマップ

### Phase 1 — 現状整理・基盤強化（今すぐ）

**目的：** 今あるものをちゃんと使えるようにする。情報の分散を減らす第一歩。

| # | 内容 | 理由 |
|---|------|------|
| 1-1 | コードの整理・デッドコード削除 | 保守性の確保 |
| 1-2 | RPO案件管理の改善（DR/CSが実際に使いやすい形に） | 最も使われるフェーズ |
| 1-3 | CRMとRPOの連携強化（受注→RPO案件の自動生成は既存） | BC→DR/CS引き継ぎの可視化 |
| 1-4 | ドキュメント整備（各画面の使い方・管理者向け設定） | 非エンジニアが使えるように |
| 1-5 | IEYASU勤怠連携 | 実装待ちのまま放置しない |

---

### Phase 2 — MK・BC強化（次のフェーズ）

**目的：** 上流のリード管理をシステムに乗せる。kintone・スプシからの脱却。

| # | 内容 | 備考 |
|---|------|------|
| 2-1 | MKリード管理（問い合わせ企業・アポ管理） | kintone情報の集約 |
| 2-2 | 広告指標ダッシュボード（CV数・ビュー数など） | スプシからAPI連携 or 手入力 |
| 2-3 | MK→BC引き継ぎフロー（アポ確定→CRM案件化） | 現状は手動 |
| 2-4 | BCの長期化案件ステータス追加 | BC担当者と要相談 |

---

### Phase 3 — HR準備フェーズのサポート（受注後）

**目的：** CR/ST/ANの作業をシステム上で管理。DRへの引き継ぎをスムーズに。

| # | 内容 | 備考 |
|---|------|------|
| 3-1 | カルテ管理（クライアントが記入→システムに取り込み） | Googleフォーム連携も検討 |
| 3-2 | 媒体提案ワークフロー（ST/AN→DR引き継ぎ） | 現状スプシ管理 |
| 3-3 | クライアントごとの案件サマリーページ | CRM+RPOの横断ビュー |

---

### Phase 4 — 経理・総務のデジタル化

**目的：** 手作業が多い反社チェック・入出金をシステムでサポート。

| # | 内容 | 備考 |
|---|------|------|
| 4-1 | 反社チェック申請・進捗管理・結果通知 | MF申請→承認→Slack通知の一元化 |
| 4-2 | 入出金管理（MF連携 or 手入力） | スプシからの移行 |
| 4-3 | 請求書・契約書の発行・管理 | 総務ヒアリング後に設計 |

## 情報集約の方針

| 外部ツール | 方針 |
|-----------|------|
| kintone | APIで同期済み（案件・入金）→ 引き続き拡張 |
| スプシ（社内） | 段階的にシステムへ移行 |
| スプシ（クライアント共有） | 移行しない。リンク管理にとどめる |
| MF（マネーフォワード） | 申請受付はMFのまま。結果管理をTaskHubに集約 |
| Slack / Chatwork | クライアント連絡は現状維持。通知はSlack連携で補完 |
| IEYASU | 勤怠データをTaskHubに表示（連携実装待ち） |
