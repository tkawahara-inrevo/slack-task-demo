# Slack 統合申請・承認フロー 導入提案

**作成日**: 2026年5月14日  
**作成者**: IT部門  
**対象読者**: 経営層・IT部門

---

## 1. 提案の背景と課題

### 現状

INREVO社では現在、以下の業務ツールを併用しています。

| ツール | 用途 |
|---|---|
| **TaskHub**（社内自製）| タスク管理・CRM・RPO案件管理・Slackボット |
| **MoneyForward（MF）** | 経費精算・請求書管理 |
| **CloudSign** | 電子契約・署名管理 |

### 課題：ツールをまたいだ申請・承認の非効率

承認フローが発生するたびに、社員は以下の手順を踏む必要があります。

```
[申請者]                          [承認者]
  |                                  |
  ├─ MF/CloudSign にログイン         ├─ Slack通知を受け取る
  ├─ 申請内容を入力・送信            ├─ 別ツールを開く
  |                                  ├─ ログイン・画面遷移
  |                                  ├─ 内容確認
  |                                  ├─ 承認ボタンをクリック
  |                                  └─ Slackに戻る
```

**1件の承認に平均 3〜5分**の非生産的な操作が発生しています。月間の承認件数が多い部門では、この積み重ねが無視できないコストになっています。また、ツールを行き来する手間から **承認漏れ・対応遅延** のリスクも生じています。

---

## 2. 提案概要：Slack から申請〜承認を完結させる

### 基本コンセプト

> **Slack（TaskHub）を「申請・承認のハブ」にする**

Slackに搭載されている **Block Kit** 機能を使うと、メッセージ内にボタンを埋め込めます。承認者はSlackを離れることなく、ボタン1クリックで承認・差戻しが完了します。

### Slack Block Kit 表示イメージ

**経費精算の場合:**

```
┌─────────────────────────────────────────────┐
│ 📋 経費精算の承認依頼                        │
│                                             │
│  申請者 : 田中 太郎                          │
│  金　額 : ¥3,500（交通費）                   │
│  申請日 : 2026/05/14                        │
│  摘　要 : 顧客訪問（新宿→渋谷）              │
│                                             │
│    [✅ 承認する]    [❌ 差し戻す]            │
└─────────────────────────────────────────────┘
```

**署名依頼の場合:**

```
┌─────────────────────────────────────────────┐
│ 📝 CloudSign 署名依頼                        │
│                                             │
│  書　類 : 業務委託契約書（株式会社〇〇）      │
│  送信者 : 人事部                            │
│  期　限 : 2026/05/21                        │
│                                             │
│    [🖊 署名ページを開く]                     │
└─────────────────────────────────────────────┘
```

### なぜ TaskHub で実装するのか

TaskHubはすでに **Slack Bolt.js** で稼働しており、Slackとのリアルタイム通信基盤が整っています。

- **追加インフラ不要**: 新たなサーバー・SaaS契約は不要
- **即日デプロイ可能**: 既存のAWS Lightsail環境に追加実装するだけ
- **一元管理**: TaskHubホーム画面に「承認待ち」を集約し、全体把握が可能
- **カスタマイズ自由**: 社内固有のルールや承認フローに合わせた調整が容易

## 3. 対象連携と実装内容

### 3-1. MFクラウド経費 — 経費精算承認

**フロー:**

```
申請者がMFで経費申請
        ↓
TaskHubがMF APIをポーリング（または Webhook受信）
        ↓
承認者のSlack DM にBlock Kitメッセージを送信
        ↓
承認者が [✅ 承認する] をクリック
        ↓
TaskHubサーバーがMF APIに承認をPOST
        ↓
Slackメッセージが「✅ 承認済み（山田 花子 / 14:32）」に更新
```

**必要なもの:**
- MFクラウド経費 APIキー（会社側で発行・取得）
- MF APIエンドポイント: `GET /expenses/approval_requests`, `POST /expenses/approval_requests/{id}/approve`

---

### 3-2. MFクラウド請求書 — 請求書承認

**フロー:**

```
取引先から請求書がアップロード or 受領
        ↓
TaskHubがMF APIで未承認請求書を検知
        ↓
経理担当者のSlack DM に通知（金額・取引先・支払期日）
        ↓
担当者が [✅ 承認する] をクリック
        ↓
MFに承認済みステータスをPOST → 支払い処理へ
```

**期待効果**: 請求書の承認漏れ・支払い遅延を防止

---

### 3-3. CloudSign — 電子契約署名依頼

CloudSignはWebhookで署名依頼イベントを通知できます。

**フロー:**

```
担当者がCloudSignで契約書を送付
        ↓
CloudSign Webhook → TaskHubエンドポイントに通知
        ↓
署名者のSlack DM にBlock Kitメッセージを送信
        ↓
[🖊 署名ページを開く] → CloudSignの署名URLに直接遷移
        ↓
署名完了後、TaskHubがWebhookで受信
        ↓
TaskHubホームの「署名待ち」タスクを「完了」に更新
```

**補足**: CloudSignのURLはワンタイムリンクのため、Slackメッセージに直接埋め込みが可能。

---

### 3-4. 汎用社内申請（有給・備品・その他）

外部API連携を必要としない、**TaskHub独自の申請フロー**です。

**フロー:**

```
申請者がTaskHubホーム画面から申請フォームを入力
（種別: 有給/備品購入/その他、内容・日付・金額など）
        ↓
申請データをDB保存 + 上長にSlack DM通知
        ↓
上長が [✅ 承認] / [❌ 差戻し] をクリック
        ↓
申請者に結果をSlack DM通知
        ↓
TaskHubホームの「申請状況」に履歴として記録
```

**活用例**: 有給申請・残業申請・備品購入申請・交通費立替申請

## 4. 技術構成・実装方針

### システム構成図

```
[申請者 / 承認者]
      │
      ▼
  [Slack]
      │  Block Kit メッセージ・ボタンアクション
      ▼
[TaskHub サーバー]  ← 既存 Bolt.js + Express
      │
      ├─── MF API ────→ [MoneyForward クラウド]
      │
      ├─── CloudSign API → [CloudSign]
      │
      └─── PostgreSQL ──→ 汎用申請の記録・ステータス管理
```

### 主な実装ファイル（既存への追加）

| ファイル | 内容 |
|---|---|
| `src/features/mf-api.js` | MFクラウド経費・請求書API連携 |
| `src/features/cloudsign-api.js` | CloudSign Webhook受信・API連携 |
| `src/features/approval-api.js` | 汎用申請フロー（DB操作） |
| `index.js`（既存） | Bolt.jsアクションハンドラ追加 |
| `src/db/index.js`（既存） | `approval_requests` テーブル追加 |

### 必要なAPIキー・設定

| 項目 | 取得方法 |
|---|---|
| MFクラウド経費 APIキー | MF管理画面 → API設定 → 発行 |
| MFクラウド請求書 APIキー | 同上（権限スコープ: 請求書閲覧・承認） |
| CloudSign APIトークン | CloudSign管理画面 → 開発者設定 → 発行 |
| CloudSign Webhook URL | `https://taskhub.inrevo.jp/api/cloudsign/webhook` を登録 |

## 5. 期待効果

### 定量効果

| 指標 | 現状 | 導入後 | 改善 |
|---|---|---|---|
| 承認1件あたりの操作時間 | 約 3〜5 分 | 約 20〜30 秒 | **約85%削減** |
| 承認漏れ件数 | 月平均 2〜3件 | ほぼゼロ | Slack通知で見逃し防止 |
| 承認リードタイム | 数時間〜翌日 | 数分〜1時間以内 | 承認者がSlackを見るだけ |

### 定性効果

- **ツール切り替えストレスの解消**: 社員が1日に何度も経験するコンテキストスイッチを削減
- **承認者の心理的ハードルが低下**: Slackを開くだけで承認できるため、後回しにされにくい
- **申請状況の透明性向上**: TaskHubホームに全申請の状況を一覧表示
- **監査証跡の一元化**: 承認者・承認日時をDBに記録し、エクスポート可能
